## 2. Decisions taken

| Decision | Answer |
|---|---|
| System of record | ERPNext (`office.santiu.co.za`) — the only source of truth. No second database |
| Client onboarding surface | `/start` on santi.co.za (on-brand, welcome video, what's next, documents) — while all actions and records live in ERPNext |
| Deposit model | Quote first, then a signed Payfast link. **50% deposit** |
| VAT | **Not VAT registered.** No tax template; quote totals are net; no default tax template may be attached to Quotations |
| Pre-payment questions | Email reply-to parsed by n8n + an ask box on the quote page. Both land as Comments on the Quotation |
| Receipt | Sent by n8n (on-brand), with a Comment written back to the Project so the trail stays on the record |
| Welcome video | Placeholder frame for v1 |
| Agent layer | Phase 1 ships the pipeline; Paperclip is phase 2, pointed at the existing MCP |
| Secrets | Merchant key and passphrase live in a Cloudflare Worker, never in n8n and never in a browser |

## 3. Architecture

```
                 ┌─ santi.co.za (static, public, noindex) ────┐
   contact form  │  /quote?t=…  quote, ask box, pay button     │
   → Lead        │  /start?t=…  video, next steps, brief,      │
                 │              documents, uploads             │
                 └──────────┬─────────────────────────────────┘
                            │ token exchange (no secrets in page)
   ┌────────────────────────▼──────────────────┐   ┌──────────────────────────┐
   │  n8n.santi.co.za — sole public edge       │◄──┤ pay.santiu.co.za         │
   │  W1 lead intake                           │   │ Cloudflare Worker        │
   │  W2 quote → signed pay link               │──►│ holds merchant creds +   │
   │  W3 Payfast ITN gate                      │   │ passphrase               │
   │  W4 email reply → Comment                 │   │ /pay/:token  build+sign  │
   │  W5 /start data, brief, uploads           │   │ /_itn/validate           │
   │  W6 daily reconciliation                  │   └──────────────────────────┘
   └────────────────────────┬──────────────────┘              ▲
                            │ Frappe REST + CF Access token   │ ITN
                 ┌──────────▼──────────────────┐         ┌────┴─────┐
                 │ office.santiu.co.za         │         │ Payfast  │
                 │ Lead → Opportunity →        │         └──────────┘
                 │ Quotation → Sales Order →   │
                 │ Project + Tasks → Invoice   │
                 │ Files attached to Project   │
                 └─────────────────────────────┘
```

Why this shape: **ERPNext keeps Cloudflare Access intact — no hole is opened in it.** Payfast and the client's browser only ever reach n8n or the Worker. The static site holds no secrets and needs no backend. The Worker exists solely so the passphrase never reaches n8n, copying the arrangement that already works for Resu.

### Record lifecycle

1. Contact form → **Lead** (W1; today the webhook goes nowhere useful).
2. Qualified → **Opportunity**.
3. **Quotation** raised in ERPNext. On submit, W2 stores a token, asks the Worker for a signed link, emails quote + `/quote?t=…`.
4. Questions (email reply or ask box) → **Comments on that Quotation**. Amended scope → new version, new token, old token cleared.
5. Payment → ITN → **W3, the gate**. On pass: **Sales Order** (submitted) + **Payment Entry** (50% advance, submitted) + **Project** from template + onboarding **Tasks** + `/start` token. Then receipt email. The deposit stays an advance against the Sales Order and is reconciled to the final Sales Invoice at handover.
6. `/start` reads that Project through W5. Brief → custom fields + Comment, `custom_brief_status` → Submitted. Uploads → Files attached to the Project.
7. Delivery Tasks are what agents work, through `erpnext_mcp.py`.

## 4. ERPNext configuration

Order matters — Items before quotes, template before the gate.

**a) Service Items** (blocker for quoting; only 1 Item exists). Non-stock, each with a default Income Account and UOM: Website Design & Development, Branding / Identity, AI Engineering, AEO, Hosting, WordPress Plugin, Retainer.

**b) `svc-n8n@santiu.co.za` — a dedicated service user, not one of the agent users.** `ai-projects` is correctly denied Sales Invoice and Payment Entry; widening it would destroy the role separation already in place. Grants: Quotation read, Sales Order create+submit, Payment Entry create+submit, Project create+write, Task create+write, File create, Comment create, `Payfast ITN` full. Plus its own Cloudflare Access service token, separate from the MCP one.

**c) Custom fields**, created through the Custom Field doctype (survives upgrades), `custom_` prefixed:

| Doctype | Field | Type | Purpose |
|---|---|---|---|
| Quotation | `custom_deposit_percent` | Percent, default 50 | |
| Quotation | `custom_deposit_amount` | Currency, read-only | computed; **the only figure the ITN is checked against** |
| Quotation | `custom_quote_token` | Data, hidden, indexed | `/quote?t=…` |
| Quotation | `custom_token_expires` | Datetime | |
| Sales Order | `custom_pf_payment_id` | Data, read-only | which payment opened this order |
| Project | `custom_start_token` | Data, hidden, indexed | `/start?t=…` |
| Project | `custom_start_expires` | Datetime | 90 days, renewable |
| Project | `custom_brief_status` | Select: Awaiting / Submitted / Approved | what `/start` shows, what agents watch |

**d) `Payfast ITN` doctype — the idempotency lock.** Autonamed `field:pf_payment_id`, fields: `payment_status`, `amount_gross`, `raw_payload` (Long Text), `status` (Verified / Rejected / Processed / Failed), `sales_order` (Link), `error` (Small Text). Autonaming on the payment id means **the database rejects a duplicate insert**. That is atomic; an "if exists" check is not, and two concurrent ITN retries can both pass one.

Resu learned this the hard way and wrote it down: keying idempotency on "has this person ever paid" rather than on this payment meant *"every renewal was answered with already active: no receipt, no extended expiry, no message, no alert."* Key on `pf_payment_id`.

**e) Project Template "Client Onboarding"** — template Tasks: receipt & welcome sent · brief received · kickoff booked · brand assets received · access & credentials received · direction approved · build · review · handover. W3 instantiates it, so every paid client gets the same board and agents always know what "next" means.

**f) Lead Source + Opportunity stages** so W1 has somewhere to file a website enquiry.

## 5. The `santi-pay` Cloudflare Worker

Mirrors `resu-pay`. Route `pay.santiu.co.za/*` on the existing `santiu.co.za` zone. Reuses **`Resu/Source/src/core/payfast.js` and `src/core/md5.js` unchanged** — copied in, not rewritten.

That module is not ordinary code. It carries encoding rules verified byte-for-byte against a real ITN: spaces encoded as `+`, uppercase hex for `!'()*`, fields signed in submission order (never alphabetical), and the asymmetry that matters most — **outbound payment forms drop empty optional fields before signing, inbound ITNs must be validated over every field Payfast sent, blanks included.** Its own comment records that filtering empty fields produced the wrong hash and keeping them produced an exact match. Do not "clean this up".

Endpoints:

- `POST /pay/:token` — n8n hands it a quote token, amount and item name; returns signed Payfast fields or a redirect URL. Merchant key and passphrase stay here.
- `POST /_itn/validate` — n8n forwards the raw ITN body; the Worker recomputes the signature with the passphrase and answers valid/invalid. n8n never holds the passphrase.

Secrets by `wrangler secret put`: `PAYFAST_MERCHANT_ID`, `PAYFAST_MERCHANT_KEY`, `PAYFAST_PASSPHRASE`, plus a shared bearer token so only n8n can call these endpoints.

Note on n8n plumbing, already discovered by Resu: on this n8n instance the HTTP node must capture the validate response as a **file** (`responseFormat: "file"`, decoded via `getBinaryDataBuffer`) because JSON/text auto-parsing returned an un-drained stream when the request body is raw. Expect the same here.

## 6. n8n workflows

**W1 — lead intake.** Existing `/webhook/santi-leads` → create **Lead** in ERPNext, set source, Telegram alert. Smallest piece, ships first, stops leads dying in a webhook.

**W2 — quote → pay link.** Triggered by a Frappe **outbound Webhook** on Quotation submit, pointed at n8n. Outbound calls are not affected by Cloudflare Access, so this needs no exception and fires instantly — no polling. Computes `custom_deposit_amount` = 50% of grand total, writes `custom_quote_token` + expiry, calls the Worker for a signed link, emails quote + `/quote?t=…`.

**W3 — the ITN gate.** Path `/webhook/santi-deposit` (must not resemble `resu-pay`; both live on the same n8n). Ported from `resu-payfast-handler.json`, substituting ERPNext for Cloudflare KV and email for WhatsApp, keeping the Telegram alert on every rejection branch.

Order of checks — all of them, before any ERPNext write, treating every posted field as hostile:

1. **Signature** — via the Worker. Mismatch → reject.
2. **Source host** — must be a Payfast-published host/IP. *(New; Resu does not do this.)*
3. **Server-side validation** — POST the payload back to Payfast's validation endpoint and require confirmation. *(New; Resu validates the MD5 locally only. Fine at R45, not at four figures.)*
4. **Amount** — `amount_gross` against `custom_deposit_amount` on the Quotation the token maps to, to the cent. **Never trust an amount, item name or reference from the callback or the browser.**
5. **`payment_status`** must be complete; anything else is logged and stopped.

Then:

```
insert Payfast ITN (pf_payment_id as docname)  ← duplicate insert fails = retry, exit 200 quietly
  ↓
map to Quotation via our own token in custom_str1, never a client-supplied id
  ↓
Sales Order (submit) → Payment Entry (Receive, party = Customer, allocated against that Sales Order as an advance, submit)
  ↓
Project from template + Tasks + custom_start_token
  ↓
mark ITN Processed → receipt email + /start link → Comment on Project
```

The webhook returns **200 immediately** and processes after; Payfast retries slow or failed responses, and a retry storm mid-write is how duplicates get made.

**W4 — email reply parser.** Watches the quote reply-to address, appends each reply as a Comment on the matching Quotation, alerts you. Ships after the ask box, which covers questions in the meantime.

**W5 — `/start` and `/quote` data.** Token in, JSON out: client, project, open tasks, documents, brief status. Also receives brief submissions and file uploads (size cap + mime/extension allowlist) and attaches files to the Project. Downloads are proxied with short-lived URLs so ERPNext is never exposed. Rate-limited; identical generic response for expired, wrong and missing tokens.

**W6 — daily reconciliation.** Compares `Payfast ITN` rows against Sales Orders and Payment Entries, alerts on any drift or any row left `Verified` but not `Processed`. Money reconciliation is not left to chance.

## 7. The two public pages

Built the site's own way: `content/pages/quote.html` and `content/pages/start.html` through `scripts/build-site.py`, never hand-edited (per `AGENTS.md`). Both added to `deploy.sh`'s `cp -a` list; cache stamp `V` bumped. Both **`noindex, nofollow` and excluded from `sitemap.xml`** — private client surfaces.

**`/quote?t=…`** — quote lines, totals, the 50% deposit figure, expiry. Primary button *Pay 50% deposit* posts the token to n8n, which gets signed fields from the Worker and returns a redirect; **the passphrase never touches the browser**. Ask box below → Comment on the Quotation + alert. States plainly that the link expires and that an amended quote replaces it.

**`/start?t=…`** — four blocks: placeholder welcome video; *what happens next* rendered live from the Project's open Tasks so it cannot go stale against the board agents work; brief form writing to custom fields + a Comment; documents and uploads, the list being the Files attached to the Project. That last block is the durable reference point because it *is* the project record, not a copy.

**Token handling.** Random 32-byte values stored on the record with an expiry — not signed blobs — so a link is revoked by clearing a field, and amending a Quotation kills its old link. Both pages carry `<meta name="referrer" content="no-referrer">` and strip the token from the URL with `history.replaceState` after first exchange, so it cannot leak via a Referer header or a screenshot of the address bar.

## 8. Failure handling

- Verified payment, failed ERPNext write → ITN row `Failed`, raw payload kept, Telegram alert, **client not emailed**. A receipt is never sent for a record that does not exist. Retry replays from the stored payload.
- Any rejected check → its own Telegram alert naming which check failed, and a 200 to Payfast.
- W6 catches anything that slipped through silently.

## 9. Tests

Following `api/studio-chat.test.js`, already in the repo. One runnable Node test over the logic that can lose money:

- signature: valid, tampered field, missing passphrase, and an ITN body with empty fields present (the `filterEmpty: false` case — the regression most likely to be reintroduced);
- amount: exact, one cent under, one cent over;
- idempotency: duplicate `pf_payment_id` rejected by the doctype's autonaming.

**Acceptance, live.** Resu's README states Payfast "is live and takes real money — there is no working sandbox path", so the gate is proved with a **small real payment** against a throwaway Quotation, the way Resu was proved with its R5 window. Pass condition: exactly one Sales Order, one Payment Entry, one Project — and a replayed identical ITN produces none. Then the test Quotation and its records are cancelled and the payment written off.

## 10. Ship order

Each step is useful on its own.

1. **W1 lead intake** — stops losing leads today.
2. **Spine config** — Items, `svc-n8n` + CF service token, custom fields, `Payfast ITN` doctype, Project Template.
3. **`santi-pay` Worker** — ported module, secrets set, both endpoints.
4. **W2 + `/quote`** — a quote goes out with a live pay link.
5. **W3 the gate** — live acceptance payment must pass before real quotes use it.
6. **W5 + `/start`** + receipt email.
7. **W6 reconciliation.**
8. **W4 email reply parser.**
9. **Phase 2 — Paperclip** on the Oracle box (6 GB free; **arm64 images required**), employees pointed at the existing `erpnext_mcp.py`. Nothing in phase 1 depends on it.

## 11. Prerequisites

- Payfast merchant account is **live** (confirmed — Resu uses it). Needed for `santi-pay`: merchant id, merchant key, and whether a **passphrase** is set on the account. Resu's own note records that signing without a passphrase when the account has one set is the cause of `Generated signature does not match submitted signature`.
- Decide whether Santi deposits use the **same merchant account** as Resu or a separate one. Same account means Resu's and Santi's ITNs arrive with the same credentials, so `m_payment_id`/`custom_str1` namespacing must be unambiguous and each handler must reject payments that are not its own — worth deciding before step 3.
- Cloudflare Access service token for `svc-n8n`.
- Reply-to mailbox for quote emails (W4).

## 12. Non-goals for phase 1

Client logins (tokens instead), invoicing beyond the deposit and final invoice, refunds and chargebacks, WhatsApp channel, a second database, any change to how the website is built or deployed, and Paperclip.
